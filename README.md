# Ceramika

Локальная система управления производством керамической плитки. Технолог подготавливает нормативы и запускает партии, оператор выполняет маршрут, лаборатория проводит испытания и принимает решение. Все три рабочих места используют один HTTP API и одну базу SQLite.

## Запуск на Windows

| Файл | Что запускает |
| --- | --- |
| `Desktop.bat` | Настольные модули «Технолог» и «Лаборатория» |
| `Mobile.bat` | Мобильный обход линии по Wi‑Fi |
| `Start.cmd` | Оба настольных модуля и сайт оператора |
| `Technologist.cmd`, `Laboratory.cmd`, `Operator.cmd` | Одно рабочее место |

Сайт оператора доступен по адресу [127.0.0.1:8765](http://127.0.0.1:8765/). Для API используется Python 3.10 или новее. Запуск подхватывает Python из Codex или системную установку. Пакеты Python устанавливать не требуется.

| Рабочее место | Логин |
| --- | --- |
| Технолог | `tech` |
| Оператор | `operator` |
| Мастер смены | `master` |
| Лаборатория | `lab` |

Пароль демонстрационных учётных записей — `Ceramika2026`. При первом запуске в папке `data` создаётся учебная база. Данные сохраняются между запусками.

### Запуск с телефона

1. Подключите компьютер и телефон к одной сети Wi‑Fi.
2. Дважды щёлкните по `Mobile.bat` на компьютере. Оставьте окно открытым.
3. В браузере телефона откройте адрес, который появился в окне. Войдите как `operator` или `master`.

Приложение сохраняет показания, замечания и итоговый отчёт в общей базе. На компьютере, где уже запущен API, мобильный интерфейс также доступен по адресу [127.0.0.1:8765/mobile](http://127.0.0.1:8765/mobile). Чтобы завершить отдельный сервер для телефона, нажмите Ctrl+C в его окне. Если брандмауэр Windows предложит разрешить входящие подключения, выберите частную сеть.

## Демонстрация

1. На сайте оператора откройте **ПР-26044**. Партия находится на обжиге, рядом с допусками отображаются показания трёх зон печи. Введите температуру 1120 °C и длительность 38 мин, завершите обжиг. Затем начните осмотр и укажите размер образца 600 мм.
2. В настольной лаборатории откройте **Готовая продукция**. Найдите **ПР-26044** или уже ожидающую контроля **ПР-26042**. Назначьте испытание, введите водопоглощение 0,3%, отклонение размера 0 мм и прочность 45 МПа. Завершите испытание и примените допуск.
3. В приложении технолога откройте **Производственные партии** и карточку той же партии. В ней сохраняются версии нормативов, сырьё, фактические параметры и журнал. В разделе **Отчёты** можно экспортировать выпуск в CSV.

**СЫР-265** демонстрирует блокировку входного сырья, **ПР-26045** — комплектованную партию, готовую к запуску. Показания «Печь LIVE» в учебном режиме генерируются программно. Сервер принимает показания через `POST /api/telemetry` с авторизацией технолога или администратора.

## Проектирование

Откройте [Ceramika.drawio](diagrams/Ceramika.drawio) через меню **Файл → Открыть с устройства** в draw.io. Девять листов содержат четыре UML-диаграммы, физическую ERD в нотации Crow’s Foot и мобильный wireframe обхода линии. Варианты использования и прецеденты — два названия одного вида UML-диаграммы.

| Листы | Содержание |
| --- | --- |
| UML | Варианты использования, классы, последовательность, деятельность |
| ERD | Производство и нормативы, исполнение и события, лаборатория и доступ, обходы линии |
| Wireframe | Семь экранов от входа до итогового отчёта |

Физические таблицы, ключи, индексы и триггеры описаны в `schema.sql`. ERD использует названия полей из схемы. Команда `python diagrams/build.py` заново генерирует исходный файл draw.io.

## API и данные

Базовый адрес — `http://127.0.0.1:8765/api/`. Вход выполняется через `POST /api/login`. Запросы рабочих данных используют заголовок `Authorization: Bearer <token>`. JSON-ответ содержит `success`, `data`, `error` и `meta`. Для списков можно передать `limit` и `page`. Основные группы — `products`, `recipes`, `tech_cards`, `orders`, `batches`, `lab`, `incidents`, `events`, `notifications`, `telemetry`, `reports` и `inspections`. Порт 8766 обслуживает мобильный интерфейс, вход и API обходов.

Версии утверждённых рецептур и карт защищены от редактирования. SQLite ограничивает число действующих версий, проверяет сумму компонентов, запрещает привязку заблокированного сырья и закрытие партии с невыполненными обязательными шагами. Сервер проверяет полномочия и выполняет изменения партии и журнала в одной транзакции.
